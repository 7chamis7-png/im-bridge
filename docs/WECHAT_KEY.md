# 微信密钥文件：格式与边界

微信这条腿要读你本机已登录的微信数据库，需要两个文件。这两个文件**本仓库不提供，也不包含生成它们的工具**——原因见下文「为什么不附工具」。你需要自己准备好之后，把路径填进配置。

## 需要的两个文件

### 1. `GATE_WECHAT_KEYS_FILE` —— `all_keys.json`

JSON 格式，顶层结构大致是：

```json
{
  "_db_dir": "/path/to/wxid_xxx/db_storage",
  "message/media_0.db": { "enc_key": "<hex>" },
  "hardlink/hardlink.db": { "enc_key": "<hex>" }
}
```

- `_db_dir`：微信这个账号的数据库目录，代码会从它推出附件目录（`../msg/attach`）和接收文件目录（`../msg/file`）。
- 其余每一项是「某个 `.db` 文件 → 它的 SQLCipher 解密密钥（十六进制字符串）」。至少要有 `message/media_0.db` 和 `hardlink/hardlink.db` 这两条，语音和媒体索引才能解开。

### 2. `GATE_WECHAT_IMAGE_KEY_FILE`

纯文本文件，内容就是一个密钥字符串（代码直接 `readFileSync(...).trim()`），用来解开图片 `.dat` 文件。

两个文件任一缺失，代码会报错拒绝启动这条腿（`"微信媒体配置要 keysFile 和 imageKeyFile 两个路径"`），不会用默认值瞎猜路径。

## 为什么不附工具

这两个密钥平时躺在微信客户端进程的内存里，没有官方接口能直接要到——拿到它们的办法，社区里已经有人做过（比如曾经流传的 PyWxDump 系列），但那类工具后来被下架了，原因包括：

1. **账号风险**：往聊天客户端进程里探测/注入这类动作，容易被平台的风控识别，触发限制甚至封号。这不是理论推测——这个项目自己的账号就因为类似的操作被处罚过一次。
2. **分发风险**：公开一个「从正在运行的客户端内存里扒密钥」的现成工具，比公开「怎么用密钥」风险高得多，而且这种工具很容易被挪去对付别人的账号，不只是自己的。

所以本仓库的立场是：**只读密钥、不生产密钥**。拿密钥这一步，留给你自己决定要不要做、用什么办法做、承担多大的账号风险。

## 风险提示

- 这条腿设计成**读库是只读**（不改微信的数据库文件），相对安全；但获取密钥的那一步风险在客户端那边，跟这个项目的读库行为是两件事。
- 真正容易触发风控的是**自动发送**，不是读。发送默认走无障碍点击模拟（`GATE_WECHAT_SENDER_MODE` 不设时），有一个发送间隔/串行锁的设计（`GATE_WECHAT_SEND_LOCK`），建议保留随机间隔、不要去掉，也不要把发送频率调得比正常人手动聊天快。
- 换了新设备登录、或者微信客户端升级，密钥通常会变，需要重新来一遍你自己的获取流程。

## 配置完整清单

跟微信这条腿有关的变量：

| 变量 | 说明 |
|---|---|
| `GATE_WECHAT_KEYS_FILE` | 上面说的 `all_keys.json` |
| `GATE_WECHAT_IMAGE_KEY_FILE` | 上面说的图片解密 key 文件 |
| `GATE_WECHAT_WHITELIST_FILE` | 读库白名单，只收这里面的人的话 |
| `GATE_WECHAT_SENDER` | 出站脚本路径 |
| `GATE_WECHAT_TARGET` | 发给哪个聊天窗口（无障碍模式靠窗口标题认人）|
| `GATE_WECHAT_SEND_LOCK` | 出站串行锁，微信只有一个窗口，两边抢会互相拖死 |
